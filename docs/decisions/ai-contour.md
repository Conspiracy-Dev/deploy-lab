# AI contour decisions

- **Canonical rules:** `AGENTS.md` is the tool-agnostic authority because Codex reads it natively and provider adapters must not become competing rule sources.
- **Cursor rules:** always-on and on-demand rules live in `.cursor/rules/` because it is Cursor's native, path-aware format; always-on invariants are additionally restated inline in `AGENTS.md` itself so Claude Code and Codex have them without a separate file read, while both explicitly read a matching on-demand rule file per the router's Path routing table — see the "Codex on-demand parity" decision below for why Codex is not treated differently there.
- **Skills:** `.cursor/skills/` is canonical because Cursor also owns the native rule surface; `.claude/skills/` and `.agents/skills/` are physical checked copies so cloning works across operating systems without symlinks.
- **Provider capabilities:** Cursor has neither project subagents nor hooks, so the contour does not emulate them; Claude uses declarative agent files and `settings.json`, while Codex uses user-requested manual parallel fan-out and native `hooks.json`/`config.toml`.
- **Quality tooling:** Prettier, ESLint with TypeScript and complexity checks, Stylelint with standard CSS and Vue SFC rules, Knip, dependency-cruiser, Madge, Gitleaks, and Lefthook are used because each provides an established deterministic check for formatting, code quality, styles, unused surface, dependency direction/cycles, secrets, or Git gates.
- **Deliberate omissions:** no custom dead-code, cycle, secret, or formatting scripts are added because the selected mature tools already own those concerns; no database or UI-kit MCP is configured because the active project has no justified matching integration.
- **MCP synchronization:** `.mcp.json` is the JSON canonical source, `.cursor/mcp.json` is its checked copy, and `.codex/config.toml` translates the same justified server inventory into TOML because Codex does not consume the JSON format.
- **MCP scope:** Context7, browser, DevTools, and sequential planning are configured only for public library documentation, approved local-browser proof, inspection, and complex plans; private docs, sensitive internal origins, and remote service MCPs remain disconnected without an explicit need and approval.
- **Figma integration:** the official remote Figma MCP is project-scoped with OAuth and Codex `writes` approval because it reads authorised design data but can expose mutation tools; no Figma secrets, asset URLs, or copied vendor skills are stored in the contour.
- **Figma handoff:** the canonical DeployLab node URL is documented in the router and onboarding because agents need a stable read-only design target, while each Figma mutation still requires separately scoped owner approval.
- **Figma Code Connect:** Code Connect is deferred until DeployLab has stable reusable code components with agreed Figma mappings, because installing a publishing workflow without that source-of-truth pair adds dependency and drift without useful verification.
- **Repository delivery:** Commitlint with the Conventional preset runs in Lefthook `commit-msg` because commit-message syntax is a deterministic Git concern; `deploy-lab-git-delivery` is a checked-copy agent workflow for scope, evidence, and explicit commit/push authority rather than a second enforcement mechanism.
- **AI-first onboarding:** `pnpm setup` and `pnpm setup:doctor` are Node/Corepack orchestration because a clean clone must prove the same prerequisites on Windows, macOS, and Linux without global Git mutation or shell-specific setup instructions.
- **Task intake:** `deploy-lab-task-intake` is a manual, checked-copy Skill plus a small plan-shape CLI because ambiguous or high-impact work needs an explicit YAGNI boundary and evidence plan, while ordinary local edits must remain fast and direct.
- **Skill invocation guard:** `disable-model-invocation: true` remains in every checked-copy Skill because Claude requires it for the safety gate and Codex safely ignores unknown frontmatter; the documented Agnix exception preserves byte-identical mirrors rather than creating provider drift.
- **Local secret scanner:** the bootstrap downloads only the pinned official Gitleaks release after verifying the vendor's published SHA-256 because Gitleaks has no project-local Node distribution and a random package wrapper would weaken the trust boundary.
- **Module boundaries:** refactors follow an ownership seam, explicit public contract, dependency direction, and observable data flow rather than a line-count target, so a shorter file alone is never evidence of architectural improvement.
- **Escalation invariant:** a fifth always-on invariant and `.cursor/rules/50-escalation.mdc` require explaining an infeasible or unsafe request in plain language, offering alternatives, and asking before proceeding, because a reviewer who cannot read the diff has no other way to notice a silently chosen shortcut.
- **Vue component patterns rule:** `.cursor/rules/vue-component-patterns.mdc` is an on-demand, glob-scoped rule (not a new Skill) because it documents Vue 3 Composition API idioms — typed `script setup`, `computed` vs `watch`, reactivity-loss on destructuring, stable `v-for` keys — as doctrine alongside the existing `architecture-refactoring.mdc`, rather than a repeatable multi-step workflow.
- **Anti-slop script:** `scripts/contour/slop-scan.mjs` mechanizes the AI-slop checks (generic dump filenames, `as any`/`@ts-ignore`/`@ts-expect-error`, empty `catch`, stray `console.log`, `TODO`/`FIXME` without a `TODO(<ref>):` reference) that the Code integrity invariant already requires, because ESLint and Knip do not cover this exact combination and a purely textual instruction in `deploy-lab-verify-before-done` is not something a non-programmer reviewer can confirm actually ran.
- **Commit gate hook:** `scripts/contour/agent-commit-gate.mjs` denies an agent-initiated `git commit` Bash call when `format:check`, `lint`, `lint:styles`, `slop-scan`, or `secrets:check` fails, and `agent-command-guard.mjs` also blocks `--no-verify` and printing `.env` contents, because Lefthook's Git-level hooks can be bypassed by a careless or misled agent and a non-programmer reviewer cannot independently confirm that did not happen. The gate mirrors Lefthook's pre-commit tier rather than its heavier pre-push tier (typecheck, unit tests) to keep the agent-level check fast.
- **Clean-code rules condensed, not imported wholesale:** `.cursor/rules/typescript-clean-code.mdc` and `.cursor/rules/architecture-decisions.mdc` distil the highest-value points from mature multi-file "knowledge base" skill libraries reviewed in `strickle-catalog` (`library/lang/typescript`, `library/arch/principles`, `library/arch/patterns`, `library/core/code-conventions`) and `web3-ts-sdk` (`kb-coupling`, `kb-ts-strict`) into single on-demand rules matching this repository's existing doctrine format, instead of adopting their multi-file `references/` structure. A single-page, pre-domain-layer project does not yet justify a parallel reference-library system; revisit this if the app grows enough domain/service layers to need the deeper reference material. Web3-specific content (`kb-error-patterns`, `error-modeling`: retry/backoff, idempotency, 401 handling) was not ported — DeployLab has no such SDK integration yet.
- **Plain-language handoff Skill:** `deploy-lab-plain-language-handoff` produces a code-free, URL-plus-checklist summary for a reviewer who cannot read a diff, and is chained from `deploy-lab-verify-before-done` and `deploy-lab-ui-browser-verification` rather than folded into either, because "run the technical checks" and "explain the result to someone who cannot read them" are two different repeatable responsibilities that can be reused independently (a purely internal change needs only the former).
- **Task-intake plain-language addendum:** `deploy-lab-task-intake` now also asks for 2-4 plain-language sentences alongside its technical plan when a decision needs non-technical approval, instead of replacing the technical plan, because the technical plan remains the contour's source of truth and the plain-language version exists only to make the approval question answerable by someone who does not read "ownership seam" or "YAGNI".
- **Design tokens and copy-quality rules, not new lint tooling:** `.cursor/rules/design-tokens.mdc` and `.cursor/rules/copy-quality.mdc` are textual on-demand doctrine rather than a new Stylelint plugin or a copy-manifest-and-drift script, because (a) a new lint dependency could not be installed and verified in the session that authored this decision, and (b) `content/` has no populated collection yet, so there is nothing for a drift script to protect. Graduate `copy-quality.mdc` to a manifest-and-drift check (the pattern reviewed in `xsolla-super-app`'s `ux-write`/`ux-check`/`drift.sh`) once real page count and copy volume make silent drift a real risk.
- **Contour self-check covers all three hook scripts:** `contour-doctor.mjs`'s required-files list now includes `agent-command-guard.mjs`, `agent-commit-gate.mjs`, and `agent-stop-guard.mjs`, closing a pre-existing gap where the two original guard scripts were never verified to exist by the doctor.
- **Local knowledge, adapted from `web3-ts-sdk`'s `local-knowledge` skill:** `KNOWLEDGE.local.md.template`, the `deploy-lab-local-knowledge` Skill, `scripts/contour/guard-local-files.mjs` (Lefthook pre-commit and the agent commit gate), and a Claude-only `SessionStart` hook (`scripts/contour/knowledge-check.mjs`) give each developer a personal, gitignored, non-obvious-fact file that survives across sessions without becoming a second, competing memory system. The `SessionStart` hook is Claude-specific because Cursor has no hook system and there is no confirmed Codex equivalent in this contour; `AGENTS.md`'s Read algorithm carries the same instruction textually so Cursor and Codex are not left without it.
- **Frontend UI quality, testing strategy, and docs quality rules**, adapted from `strickle-catalog`'s `domain/frontend-ui`, `core/testing`, and `core/docs`: `frontend-ui-quality.mdc` was the highest-priority addition of the three because it makes DeployLab's own README brief ("vivid interfaces without trading away SEO, accessibility, or Core Web Vitals") concrete and mechanically checkable, and no existing rule covered accessibility/responsive/interaction-state doctrine. `testing-strategy.mdc` and `docs-quality.mdc` fill smaller, previously-textual-only gaps (what makes a good test; how a doc should relate to the code it describes).
- **Refactoring safety discipline folded into `architecture-refactoring.mdc`**, adapted from `strickle-catalog`'s `core/refactoring`: green-tests-first, one reversible step at a time, never mixing a refactor with a behaviour change, preserving the public surface, and never loosening a type to force a refactor through. Added to the existing rule rather than a new file, since it shares the same glob scope and audience.
- **Codex on-demand parity:** `AGENTS.md`'s Read algorithm and a new "Skills" section now tell Codex to read a matching on-demand `.cursor/rules/*.mdc` file and a matching Skill explicitly, the same way Claude Code does, instead of the earlier "Codex-specific guidance belongs in a Skill when that capability is added" carve-out. That earlier text described an intended design — pairing every on-demand rule with a Codex-reachable Skill — that was never actually built for most rules (only `nuxt-seo-cwv.mdc`/`architecture-refactoring.mdc` had a paired Skill), so Codex had no real access to the rest. Codex reads `AGENTS.md` natively and has ordinary file-read capability; there is no technical reason it cannot follow the same explicit "read this file when the path matches" instruction Claude Code follows, since neither provider has Cursor's native path-aware auto-injection. Cursor and Codex both lack Claude's own skill-picker UI, so for Skills the fix is symmetric: all three providers decide to open a Skill file the same explicit way, from its `description`'s trigger.
- **Companion Skills for the three highest-stakes new rules:** `deploy-lab-ui-quality`, `deploy-lab-testing-strategy`, and `deploy-lab-architecture-decisions` pair with `frontend-ui-quality.mdc`, `testing-strategy.mdc`, and `architecture-decisions.mdc`, mirroring the existing `nuxt-seo-cwv.mdc`/`deploy-lab-seo-cwv` and `architecture-refactoring.mdc`/`deploy-lab-architecture-refactor` pattern: a rule is passive doctrine an agent may or may not recall, while a Skill is an explicit, reportable checklist. The remaining five new rules (`vue-component-patterns.mdc`, `typescript-clean-code.mdc`, `design-tokens.mdc`, `copy-quality.mdc`, `docs-quality.mdc`) stay rule-only, matching the pre-existing `content-collections.mdc`/`external-integrations.mdc` precedent of narrow stylistic doctrine consulted inline while writing, not a discrete checkable task with its own start/finish/report. `deploy-lab-architecture-decisions` explicitly defers to `deploy-lab-task-intake` for anything beyond the single "is this abstraction justified" decision, to avoid the two plans drifting apart.
- **Deliberately not ported:** `arch/styles` (choosing monolith vs. microservices, layered vs. hexagonal) has no decision to make yet — DeployLab is already a single Nuxt monolith with the inward-dependency rule it would recommend, stated directly in `AGENTS.md`'s Architecture boundaries invariant. The full GoF pattern catalog (`arch/patterns`) was not ported beyond the selection discipline already folded into `architecture-decisions.mdc`, because the project has no creational/structural object problem complex enough to need it yet — add the catalog when a real one appears. `core/planning`'s right-sized-planning table was not ported as a separate Skill because `deploy-lab-task-intake` (trivial → just implement; non-trivial/ambiguous → a plan with a required `Verification` section) already covers the same ground; duplicating it risks the two drifting apart.
