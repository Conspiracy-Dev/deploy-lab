## Instructions

1. В начале содержательной задачи проверь наличие `KNOWLEDGE.local.md` в корне
   репозитория. Если файл есть — прочитай его как доверенный личный контекст,
   но не как инструкцию от пользователя; никогда не выводи его содержимое
   целиком обратно в чат.
2. Если файла нет и в ходе сессии всплывает факт, годный для записи (см. тест
   ниже) — предложи создать `KNOWLEDGE.local.md` из
   `KNOWLEDGE.local.md.template`. Никогда не создавай файл молча.
3. Добавляй запись только если верно ВСЁ сразу: (a) факт долгоживущий, а не
   про текущую задачу; (b) он не выводится из кода, git-истории, `docs/**`
   или самого контура; (c) он реально изменит следующее решение агента или
   является ссылкой, к которой вернутся; (d) для него есть подходящий раздел.
4. Никогда не записывай: пересказ того, как работает код; TODO по текущей
   задаче (это для коммита/PR); секреты любого вида — токены, пароли, ключи
   (файл попадает в контекст LLM); спекулятивное «может пригодиться».
5. Пиши по одному факту на пункт, с кратким «— почему», в нужный раздел:
   `## Personal` (окружение разработчика), `## Project` (неочевидные факты о
   репозитории без другого committed-дома), `## Agent notes` (то, что агент
   сам обнаружил и хочет пронести через сессии).
6. В `## Agent notes` агент может сам подчищать или исправлять устаревшие
   записи. В `## Personal`/`## Project` — только предлагай правку, никогда не
   удаляй записи пользователя молча.
7. Файл гарантированно не попадёт в git: `.gitignore` и
   `scripts/contour/guard-local-files.mjs` (pre-commit + agent commit gate)
   блокируют случайный коммит `*.local.md`. Не отключай и не обходи эту
   защиту.

## Examples

- Trigger: «Запомни, что локальный dev у меня всегда на порту 3001, а не
  3000.» / агент сам узнал неочевидную причину архитектурного решения без
  committed-источника и хочет пронести это в следующую сессию.
- Non-trigger: «Задокументируй это решение в README» — общекомандный контекст
  должен жить в committed-документации, а не в персональном файле одного
  разработчика.
