## Instructions

1. Прочитай `.cursor/rules/frontend-ui-quality.mdc` и изменённый компонент или страницу до проверки.
2. Проверь разметку: используются ли правильные семантические элементы (`button`, `a`, `nav`, заголовки по порядку) до ARIA; клавиатурная доступность и видимый focus для каждого интерактивного элемента.
3. Проверь responsive: fluid `clamp()`/intrinsic Grid/Flexbox вместо произвольных breakpoints; при значимом responsive-изменении получи mobile viewport screenshot через `deploy-lab-ui-browser-verification`.
4. Проверь покрытие состояний для каждого интерактивного элемента: loading, empty, error, disabled, focus — не только happy path; проверь `prefers-reduced-motion`.
5. Проверь WCAG-контраст, что смысл не передаётся только цветом, и что цвета/отступы/радиусы взяты из `tokens.css` (`design-tokens.mdc`), а не хардкод.
6. Сообщи по каждому пункту чек-листа: пройден или найден пробел. При пробеле предложи наименьшее исправление, не переписывая компонент целиком; не объявляй задачу готовой, пока пробел не устранён или явно не согласован с пользователем.

## Examples

- Trigger: «Проверь, что новая карточка доступна и адаптивна» / перед завершением задачи, добавившей новый интерактивный элемент.
- Non-trigger: «Проверь SEO-метаданные страницы» — используй `deploy-lab-seo-cwv`.
